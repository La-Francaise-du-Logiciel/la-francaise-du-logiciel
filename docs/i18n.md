# Internationalisation

Le site est publié en français et en anglais. Le français est la langue
sans préfixe (`/conseil`), l'anglais vit sous `/en` avec des slugs traduits
(`/en/consulting`). Toutes les pages restent prérendues statiquement.

## Architecture

```
lib/locale.ts     Les primitives : locales, langue racine, langue de repli,
                  négociation Accept-Language, nom du cookie. Aucun import de
                  catalogue, pour que le proxy reste léger.
lib/routes.ts     La carte des chemins, par page et par langue. Source unique
                  de vérité pour les liens, le sélecteur et le proxy.
lib/i18n.ts       Point d'entrée de l'application : getMessages(locale),
                  format(), et les réexports de lib/locale.
messages/fr.ts    Le catalogue de référence.
messages/en.ts    La traduction, vérifiée sur la forme de fr.ts.
proxy.ts          Redirections de langue et réécriture des URL françaises.
```

L'arbre de routes est générique :

```
app/[locale]/page.tsx          la page d'accueil
app/[locale]/[slug]/page.tsx   toutes les autres pages
components/views/              le corps de chaque page, une fois pour toutes
                               les langues
components/views/index.ts      quel identifiant de page rend quelle vue
```

Le slug étant traduit, il ne peut pas servir de nom de dossier : il est
résolu vers un identifiant de page par `pageIdBySlug`, puis vers une vue par
le registre. C'est ce qui évite de dupliquer un dossier de routes par langue.

## La langue traverse l'application par les props

`getMessages(locale)` exige une locale. Les pages la lisent depuis leur
segment de route et la passent aux composants. Aucun composant ne devine la
langue, et il est donc impossible d'en afficher une par erreur.

## Ce que fait le proxy

`proxy.ts` s'exécute sur chaque requête de page, dans cet ordre :

1. `/fr/...` est la forme interne d'une URL française, jamais une URL
   publique : redirection 308 vers le chemin sans préfixe.
2. Négociation : si le visiteur ne lit pas le français, redirection 307 vers
   la version anglaise de la page demandée. Le cookie posé par le sélecteur
   l'emporte sur l'en-tête `Accept-Language`.
3. Réécriture des URL françaises vers la branche `/fr` de l'arbre de routes.
   L'adresse affichée ne change pas, et la page servie reste statique.

Deux garde-fous :

- **Sans en-tête `Accept-Language`, aucune redirection.** C'est ainsi
  qu'arrivent les robots d'indexation et les clients HTTP nus : ils restent
  sur l'URL canonique française plutôt que d'être devinés.
- **Les URL préfixées ne sont jamais renégociées.** `/en/...` est une demande
  explicite, on ne renvoie pas le visiteur ailleurs.

Les redirections négociées portent `Vary: Accept-Language, Cookie`. Next
impose son propre `Vary` sur les réponses réécrites : si un cache HTML
partagé est un jour placé devant l'application, il devra être configuré pour
varier sur `Accept-Language` et `Cookie`.

## Le cookie

Le sélecteur de langue écrit un cookie `locale` (`fr` ou `en`), et lui seul :
il n'est jamais posé automatiquement. C'est le seul cookie du site, et la
page Confidentialité le décrit dans les deux langues. Si ce comportement
change, cette page doit changer avec lui.

## Ajouter une langue

Il n'y a pas de fichier de route à dupliquer.

1. Ajouter la locale à `locales` dans `lib/locale.ts`, avec son étiquette
   Intl dans `INTL_TAGS` et son nom dans `LOCALE_LABELS`.
2. Ajouter une colonne par page dans `PAGES`, dans `lib/routes.ts`.
3. Copier `messages/fr.ts` vers `messages/xx.ts` et traduire. Les liens
   passent par `path(id, 'xx')`, jamais par une chaîne écrite à la main.
4. Enregistrer le catalogue dans `CATALOGUES`, dans `lib/i18n.ts`.

TypeScript signale toute clé manquante ou mal orthographiée à l'étape 4, et
`generateStaticParams` prérend les nouvelles pages sans autre intervention.

## Ajouter une page

1. Une entrée dans `PAGES` (`lib/routes.ts`), avec son chemin dans chaque
   langue.
2. Son identifiant dans `CATALOGUE_PAGES`.
3. Son contenu sous `pages` dans chaque catalogue.
4. Une vue dans `components/views/`, puis une ligne dans
   `components/views/index.ts`.

## Points de vigilance

- **Le chemin courant côté client est réécrit.** `usePathname()` renvoie
  `/fr/conseil` au rendu serveur alors que le navigateur affiche `/conseil`.
  Tout code qui compare ou transforme le chemin courant doit d'abord le
  normaliser avec `publicPath()`.
- **Les identifiants d'ancre ne sont pas du contenu.** `ANCHORS` reste
  identique dans toutes les langues, pour qu'un composant partagé puisse
  écrire le sien en dur.
- **Page 404.** Le layout racine étant sous un segment dynamique, une page
  404 personnalisée demanderait le drapeau expérimental
  `experimental.globalNotFound`. Le site sert donc la page par défaut de
  Next, comme avant l'ajout de l'anglais.
